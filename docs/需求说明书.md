## 1. 概述

### 1.1 背景

家庭日常收支分散在微信/支付宝、现金消费和记忆中，难以汇总与复盘。希望通过一款 Android 应用，将每一笔**收入**与**支出**结构化记录，实现家庭财务数字化，并通过图表直观了解消费结构与收支趋势。

### 1.2 产品定位

**家账本**是一款面向个人/单家庭使用的**离线记账应用**：快速记流水、分账户管理、自定义分类，并用图表完成月度复盘。产品架构按「家庭事务平台」预留扩展能力，但 **v1.0 仅交付记账与统计能力**。

### 1.3 产品愿景

> 先把家里的钱花清楚、记明白；以后还能在同一个 App 里扩展更多家事记录。

### 1.4 本期目标（v1.0 / MVP）

| 目标 | 说明 |
|------|------|
| 记清楚 | 每笔收入/支出可快速录入，支持账户与分类 |
| 算准确 | 金额计算无浮点误差，统计口径一致 |
| 看得懂 | 提供分类占比、收支趋势、月度对比图表 |
| 数据安心 | 全部数据存于手机本地，无需联网、不上云 |

### 1.5 非目标（v1.0 明确不做）

- 预算设置与超支提醒
- 云同步、账号登录、多设备协同
- 银行/支付 App 自动导入账单
- 应用商店上架与运营（首期自用）
- 多家庭成员分别记账（仅一人记账，不区分「谁花的」）
- 投资理财、股票基金等专业模块
- 联网依赖型功能（天气、汇率 API 等，除非用户主动触发且可离线降级）

### 2.3 典型场景

**场景 A：超市购物后记账**  
打开 App → 点击「记一笔」→ 选「支出」→ 输入金额 → 选分类「购物」→ 选账户「微信」→ 保存。

**场景 B：月底复盘**  
进入「统计」→ 选择「本月」→ 查看支出分类饼图、每日支出折线、与上月对比柱状图 → 查看总收入/总支出/结余。

**场景 C：纠正错误记录**  
流水列表 → 点击某条 → 编辑金额或分类 → 保存；或删除（二次确认）。

**场景 D：换机迁移**  
设置 → 导出加密备份到本地文件 → 新手机安装 App → 导入备份。

## 5. 数据需求

### 5.1 实体关系（概念模型）

```
Account（账户） 1 ── N Transaction（流水）
Category（分类） 1 ── N Transaction（流水）

Transaction
  - type: INCOME | EXPENSE
  - amount: 金额（逻辑 DECIMAL，见 5.2）
  - categoryId, accountId
  - occurredAt, note
  - createdAt, updatedAt
```

v1.0 **不包含** Member（成员）、Budget（预算）、CloudUser（云账号）实体。

### 5.2 金额存储规范

| 规则 | 说明 |
|------|------|
| 禁止使用 Float/Double 存储金额 | 使用 INTEGER 存「分」或 TEXT 存 DECIMAL 字符串，业务层 BigDecimal |
| 展示 | 统一保留 2 位小数 |
| 运算 | divide 必须指定 scale 与 RoundingMode |
| 统计聚合 | 在数据库层 SUM，避免内存全量加载超大数据集 |

### 5.3 字段定义：Transaction（流水）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 是 | 主键 |
| type | Enum | 是 | INCOME / EXPENSE |
| amount | Long | 是 | 单位：分 |
| categoryId | Long | 是 | 外键 |
| accountId | Long | 是 | 外键 |
| occurredAt | Long/Instant | 是 | 发生时间戳 |
| note | String | 否 | 备注 |
| createdAt | Long | 是 | 创建时间 |
| updatedAt | Long | 是 | 更新时间 |

### 5.4 字段定义：Category（分类）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 是 | 主键 |
| name | String | 是 | 显示名 |
| type | Enum | 是 | INCOME / EXPENSE |
| icon | String | 否 | 图标 key |
| color | Int | 否 | 色值 |
| isPreset | Boolean | 是 | 是否预设 |
| isHidden | Boolean | 是 | 是否隐藏 |
| sortOrder | Int | 是 | 排序 |

### 5.5 字段定义：Account（账户）

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | Long | 是 | 主键 |
| name | String | 是 | 账户名 |
| icon | String | 否 | 图标 key |
| color | Int | 否 | 色值 |
| isPreset | Boolean | 是 | 是否内置 |
| isDisabled | Boolean | 是 | 停用后不可在新流水中选择 |
| sortOrder | Int | 是 | 排序 |

### 5.6 数据量级与性能（自用预期）

| 指标 | 目标 |
|------|------|
| 流水条数 | 设计支持 1 万+ 条 |
| 列表 | 分页加载，每页 20～50 条 |
| 图表 | 按周期聚合查询，禁止一次加载全部流水到内存算图 |

## 6. 非功能需求

| 类别 | 要求 |
|------|------|
| **隐私** | 数据仅存本机；隐私政策说明无上传、无账号 |
| **离线** | 核心功能 100% 离线可用 |
| **网络** | v1.0 不依赖网络；尽量不声明 INTERNET 权限 |
| **安全** | 应用锁；备份文件建议 AES 加密，密钥由用户备份密码派生 |
| **可靠性** | 写库失败有提示；关键操作不吞异常 |
| **兼容性** | 最低 Android 8.0（API 26），目标 API 34+ |
| **易用性** | 记一笔主路径 ≤ 3 步；删除需二次确认 |
| **可扩展** | 模块化/feature 分包，便于后续加 Tab 与新领域模块 |
| **可维护** | 自用版本也需清晰分层：UI / Domain / Data |

## 7. 业务规则汇总

| 规则 ID | 规则 |
|---------|------|
| BR-01 | 结余 = 周期内收入合计 − 支出合计 |
| BR-02 | 统计周期以 `occurredAt` 为准 |
| BR-03 | 同一类型下分类名称不可重复 |
| BR-04 | 账户名称不可重复 |
| BR-05 | 有流水关联的账户不可删除，仅可停用 |
| BR-06 | 删除分类前必须无关联流水，或提供迁移（v1 采用「有流水则不可删」） |
| BR-07 | v1.0 不做预算相关逻辑 |
| BR-08 | 不做多人/成员维度统计 |
