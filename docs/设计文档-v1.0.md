## 1. 设计目标与范围

### 1.1 设计目标

基于需求文档，完成一套可直接进入开发阶段的技术与实现设计，确保：

- 核心能力（记账、流水、统计、分类、账户）可稳定交付；
- 金额计算准确、统计口径统一；
- 纯离线、无云依赖、隐私可控；
- 结构清晰，便于后续扩展预算/周期账/云同步等功能。

### 1.2 本文档范围（v1.0）

- Android 端架构与模块划分；
- 数据模型、数据库设计与索引策略；
- 核心业务流程与关键交互；
- 统计口径与聚合实现；
- 备份恢复与应用锁设计；
- 测试策略、发布里程碑与风险控制。

### 1.3 非范围（v1.0 不设计实现）

- 云同步、账号体系、多设备协同；
- 预算提醒、周期自动记账；
- 自动账单导入；
- 多成员维度统计。

## 2. 技术选型与总体架构

### 2.1 技术栈

- 语言：Kotlin
- UI：Jetpack Compose + Material3
- 架构：MVVM + Clean-ish 分层（UI / Domain / Data）
- 本地存储：Room（SQLite）
- 依赖注入：Hilt
- 图表：Vico（优先 Compose 友好）
- 序列化：kotlinx.serialization（备份数据结构）
- 安全：Android Keystore + BiometricPrompt（应用锁/密钥保护）

### 2.2 分层架构

1. **UI 层**
   - Compose 页面 + ViewModel 状态驱动；
   - 只处理展示状态、用户事件、路由跳转。
2. **Domain 层**
   - UseCase 编排业务规则（新增流水、删除校验、统计聚合等）；
   - 保证口径一致（如全部以 `occurredAt` 归属统计周期）。
3. **Data 层**
   - Repository + Room DAO；
   - LocalDataSource 负责 DB 与事务；
   - BackupDataSource 负责导入导出文件。

### 2.3 模块划分（建议）

```
app
├── core
│   ├── common        // 通用工具、Result、Dispatcher、扩展
│   ├── ui            // 主题、通用组件、设计系统
│   ├── database      // Room DB、Entity、Dao、Migration
│   ├── model         // 领域模型、枚举、值对象
│   └── backup        // 备份恢复、加密、文件读写
└── feature
    ├── home          // 首页
    ├── ledger        // 流水列表/筛选/详情/编辑
    ├── entry         // 记一笔
    ├── stats         // 统计图表
    ├── category      // 分类管理
    ├── account       // 账户管理
    ├── settings      // 备份、安全、关于
    └── lock          // 应用锁
```

> 若首版需要降低工程复杂度，可先做单模块，按 package 分层，确保边界后续可平滑拆分。

## 3. 数据模型与数据库设计

### 3.1 金额规范

- DB 持久化使用 `Long` 存储“分”（避免浮点误差）；
- 业务层与展示层转换为 `BigDecimal`（保留 2 位）；
- 除法运算统一指定 `scale=2` 和 `RoundingMode.HALF_UP`。

### 3.2 实体定义（核心字段）

#### 3.2.1 TransactionEntity

- `id: Long`（PK，自增）
- `type: String`（INCOME/EXPENSE）
- `amountCent: Long`（>0）
- `categoryId: Long`（FK）
- `accountId: Long`（FK）
- `occurredAt: Long`（毫秒时间戳）
- `note: String?`（<=500 字符）
- `createdAt: Long`
- `updatedAt: Long`
- `isDeleted: Boolean`（可选，v1 可不用软删）

#### 3.2.2 CategoryEntity

- `id: Long`（PK）
- `name: String`
- `type: String`（INCOME/EXPENSE）
- `icon: String?`
- `color: Int?`
- `isPreset: Boolean`
- `isHidden: Boolean`
- `sortOrder: Int`
- `createdAt: Long`
- `updatedAt: Long`

#### 3.2.3 AccountEntity

- `id: Long`（PK）
- `name: String`
- `balanceCent: Long`（当前余额，单位分，v1.1 新增）
- `icon: String?`
- `color: Int?`
- `isPreset: Boolean`
- `isDisabled: Boolean`
- `sortOrder: Int`
- `createdAt: Long`
- `updatedAt: Long`

### 3.3 约束与索引

1. **唯一约束**
   - 分类：`(type, name)` 唯一；
   - 账户：`name` 唯一。
2. **外键约束**
   - `transaction.categoryId -> category.id`
   - `transaction.accountId -> account.id`
3. **关键索引**
   - `transaction(occurredAt DESC)`：流水倒序与时间筛选；
   - `transaction(type, occurredAt)`：按类型统计；
   - `transaction(categoryId, occurredAt)`：分类排行；
   - `transaction(accountId, occurredAt)`：账户筛选统计；
   - `category(type, isHidden, sortOrder)`：记一笔分类列表。

### 3.4 Room 版本与迁移

- 数据库版本：`v2`（v1.1 新增 `account.balanceCent`）
- 迁移策略：
  - v1 开发阶段允许 `fallbackToDestructiveMigration`（Debug）；
  - Release 必须提供显式 Migration。

## 4. 核心业务规则落地

### 4.1 规则映射

- 结余 = 收入合计 - 支出合计；
- 统计归属一律使用 `occurredAt`；
- 有关联流水的账户不可删除，只能停用；
- 预设分类可隐藏不可删除；
- 有关联流水的分类不可删除（v1 采取阻断策略）；
- 删除流水需二次确认；
- 所有异常禁止吞掉，必须记录日志并可感知反馈。

### 4.2 数据一致性

- 新增/编辑/删除流水后，首页与统计页使用同一聚合查询源，避免口径漂移；
- 统计查询全部走 SQL 聚合，不在内存全量遍历；
- 关键写操作使用 Room `@Transaction`，保证原子性。

## 5. 功能模块详细设计

### 5.1 记一笔（Entry）

#### 5.1.1 页面结构

- 顶部：收入/支出切换；
- 金额输入区：数字键盘、两位小数限制；
- 分类区：按类型加载可见分类；
- 账户区：默认上次使用账户；
- 时间区：默认当前时间，可修改；
- 备注区：可空，限制长度；
- 底部：保存按钮（表单校验通过可点击）。

#### 5.1.2 校验规则

- `amountCent > 0`
- 分类、账户、发生时间必填；
- 备注超长阻断并提示；
- 非法输入（多小数点、负号、字母）拦截。

#### 5.1.3 保存流程

1. ViewModel 接收 UI Intent；
2. UseCase 校验并构建 Transaction；
3. Repository 入库；
4. 返回成功事件并关闭页面；
5. 通知首页/流水/统计刷新（基于 Flow 自动订阅）。

### 5.2 流水模块（Ledger）

- 默认按 `occurredAt DESC` 查询，按天分组显示；
- 支持筛选：时间范围、类型、分类、账户；
- 详情页可编辑与删除；
- 删除前弹出二次确认。

### 5.3 统计模块（Stats，v1.2）

#### 5.3.1 周期模型 `StatsPeriodFilter`

| `StatsScope` | 用户选择 | `occurredAt` 范围 |
|--------------|----------|-------------------|
| `MONTH` | 年 + 月（默认当月） | 当月 00:00:00 ~ 月末 23:59:59.999 |
| `YEAR` | 年（默认当年） | 当年 1/1 ~ 12/31 |
| `ALL` | 无子选择 | `0` ~ `Long.MAX_VALUE`（或等价全量） |

汇总与分类占比均使用上述范围；与流水页的 `DateRangeFilter` **独立**，互不复用 UI 组件。

#### 5.3.2 图表

1. **支出分类占比（饼图）** — 三档周期均展示；SQL 同 v1.0。
2. **收支趋势（折线）** — 仅 `YEAR`、`ALL`：
   - `YEAR`：`strftime('%Y-%m')` 按月聚合，Repository 补齐 1～12 月空桶为 0；
   - `ALL`：`strftime('%Y')` 按年聚合，Repository 从最早有数据年份补至当前年。
3. **v1.2 移除**：按日趋势、最近 6 个月柱状对比、统计页分类排行列表。

#### 5.3.3 空状态

- 当前周期无收支时：汇总为 0，展示「记第一笔」；饼图/折线图区域不展示空画布。

### 5.3.4 备份交互（v1.2）

```
导出：点击按钮 → AlertDialog(密码+确认) → 校验(≥6位、一致) → SAF CreateDocument → AES-GCM 写文件
恢复：点击按钮 → SAF OpenDocument → AlertDialog(密码) → 解密校验 → 全量覆盖 DB
```

主界面不再常驻密码输入框；密码仅存在于弹窗生命周期，导出成功后由 ViewModel 清除缓存。

### 5.4 分类管理（Category）

- 预设分类：可隐藏/显示，不可删除；
- 自定义分类：新增、编辑、删除（有关联流水则阻断）；
- 同类型下名称唯一校验；
- 排序字段保留，v1 可先用固定顺序+置顶。

### 5.5 账户管理（Account）

- 首次安装初始化：现金、微信、支付宝、银行卡；
- 可新增/编辑/停用账户；
- 有关联流水不可删除；
- 记一笔默认选上次使用账户（本地偏好保存）。

### 5.6 首页（Home）

- 展示默认周期（本月）收入/支出/结余；
- 展示最近 5~10 条流水；
- 提供显眼“记一笔”入口。

### 5.7 设置（Settings）

1. **备份导出**
   - 导出 JSON（可选压缩）；
   - 文件包含版本号与导出时间；
   - 可选加密（建议 AES-GCM）。
2. **备份恢复**
   - v1 采用全量覆盖；
   - 恢复前二次确认；
   - 版本不兼容时给出明确提示。
3. **应用锁**
   - PIN 或生物识别；
   - 后台超时（默认 5 分钟）返回前台需解锁。

## 6. 状态管理与交互设计

### 6.1 ViewModel 状态模式

统一采用：

- `UiState`：页面渲染状态（Loading / Content / Empty / Error）
- `UiEvent`：一次性事件（Toast、导航、弹窗）
- `UiAction`：用户动作（点击、输入、筛选）

### 6.2 数据流

- DAO 返回 `Flow`；
- Repository 组合数据；
- ViewModel 使用 `stateIn` 转为可观察状态；
- 页面自动响应数据变化，减少手动刷新逻辑。

## 7. 性能与可靠性设计

### 7.1 性能策略

- 列表分页：20~50 条/页；
- 图表只查聚合结果，不拉全量流水；
- 复杂筛选尽量下推 SQL 层；
- 启动时初始化数据（预设分类/账户）采用幂等逻辑。

### 7.2 稳定性策略

- DB 写入失败有用户可感知提示；
- 恢复流程发生异常时终止并回滚；
- 异常日志结构化输出（避免打印敏感信息）；
- 核心流程补充埋点（本地日志），便于自用排查。

---

## 8. 安全与隐私设计

- 默认不申请 `INTERNET` 权限（若后续需要联网功能需单独评估）；
- 数据库位于应用私有目录；
- 备份文件可选密码加密；
- 应用锁密钥保存在 Android Keystore；
- 隐私页明确说明：数据仅本地、不上传服务器。

## 11. 风险与应对

1. **图表库兼容性风险**
   - 预案：先封装图表数据层，必要时替换库不影响业务层。
2. **备份恢复版本兼容风险**
   - 预案：备份结构带版本号，恢复时做版本分支处理。
3. **数据量增长导致统计卡顿**
   - 预案：强化 SQL 聚合与索引，避免内存全量计算。
4. **应用锁误触发影响体验**
   - 预案：超时时间可配置，弱提醒引导用户理解行为。
